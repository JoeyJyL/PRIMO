## Sets and Indices

- $V = \{0, 1, 2\}$: launch/landing locations (0 = depot)
- $C = \{1, 2, 3, 4, 5\}$: customers
- $D = \{1, 2\}$: drones
- $O$: set of all feasible operations (enumerated offline)

## Parameters

- $truckTime_o$: truck travel time for operation $o$ (from launch to landing location)
- $droneTime_{od}$: flight time of drone $d$ in operation $o$
- $hasDrones_o$: 1 if operation $o$ uses any drones
- $\lambda = 30$ s: launch penalty per operation
- $cover(o, j) \in \{0,1\}$: 1 if operation $o$ services customer $j$
- $lp(o, l) \in \{0,1\}$: 1 if operation $o$ launches from location $l$
- $rp(o, l) \in \{0,1\}$: 1 if operation $o$ lands at location $l$

## Decision Variables

- $x_o \in \{0, 1\}$: 1 if operation $o$ is selected
- $T_o \geq 0$: time duration of operation $o$ (explicit variable, NOT precomputed parameter)

## Objective

$$\min \sum_{o \in O} T_o$$

## Constraints

### (C1) Operation Time — Indicator Constraint Formulation

The original formulation precomputes operation time as a parameter:
$t_o = \max(truckTime_o, \max_d droneTime_{od}) + \lambda \cdot hasDrones_o$
and uses it directly as a coefficient in the objective: $\sum_o t_o \cdot x_o$.

This is replaced by **explicit time variables with indicator constraints**. The max operation is modeled implicitly: $T_o$ must be at least as large as each component time when the operation is selected.

**Truck time bound:**
$$x_o = 1 \;\Rightarrow\; T_o \geq truckTime_o + \lambda \cdot hasDrones_o$$

**Drone time bound (per drone):**
$$x_o = 1 \;\Rightarrow\; T_o \geq droneTime_{od} + \lambda \cdot hasDrones_o, \quad \forall d \in D$$

When $x_o = 0$, no indicator constraint is active, and minimization drives $T_o = 0$.

### (C2) Customer Coverage — Set Partitioning

The original uses set covering ($\geq 1$):
$$\sum_{o \in O} cover(o, j) \cdot x_o \geq 1, \quad \forall j \in C$$

This is strengthened to **set partitioning** ($= 1$):
$$\sum_{o \in O} cover(o, j) \cdot x_o = 1, \quad \forall j \in C$$

Each customer must be served by exactly one selected operation (no redundant coverage).

### (C3) Flow Conservation

$$\sum_{o \in O} lp(o, l) \cdot x_o = \sum_{o \in O} rp(o, l) \cdot x_o, \quad \forall l \in V$$

### (C4) Start at Depot

$$\sum_{o: lp(o, 0) = 1} x_o \geq 1$$

### (C5) Energy Feasibility

Enforced implicitly by restricting $O$ to energy-feasible operations only.

## Key Modeling Differences

1. **Precomputed parameter → Indicator-constrained variable**: The original embeds the $\max(truckTime, \max_d droneTime)$ computation in the data preprocessing phase and uses the result as a constant coefficient. The reformulation makes operation time an explicit decision variable $T_o$ and uses Gurobi indicator constraints to enforce the component time bounds. The $\max$ operation emerges from minimization driving $T_o$ down to the tightest bound.

2. **Set covering → Set partitioning**: Customer coverage constraints are strengthened from inequality ($\geq 1$) to equality ($= 1$), eliminating redundant coverage and tightening the LP relaxation.

2. Problem Size: Small
